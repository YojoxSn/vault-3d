Replace the `<PLACEHOLDERS>` with your own values and paste them into Claude Code, started in an **empty project folder** (not inside your vault).

## Prompt 2: everything, plus the "Iron Man" hand control

<details open>
<summary>Show prompt 2 (French)</summary>

```text
Crée-moi une visualisation 3D interactive de TOUT mon vault Obsidian (mon « second cerveau ») † avec Three.js,
contrôlable avec mes mains via la webcam, façon hologramme de Tony Stark dans Iron Man / Marvel.

## Contexte
- Mon vault Obsidian se trouve ici : <CHEMIN/VERS/MON/VAULT>
- Nom du vault : <NOM>
- App web locale : Vite + TypeScript + Three.js (sans framework lourd), lancée avec `npm run dev`. †
- Si le chemin n'est pas fourni, crée un mini-vault d'exemple dans `example-vault/` (30 à 50 notes liées) pour tester.

## Étape 1 : importer tout le vault
- Script `scripts/build-graph.ts` qui parcourt récursivement le vault (ignorer `.obsidian/`, `.trash/`, `node_modules/`).
  Les pièces jointes (images, PDF) deviennent des nœuds secondaires optionnels.
- Chaque `.md` = un nœud : { id, title, path, folder, updatedAt, excerpt (les 500 premiers caractères),
  contentHtml (markdown rendu en HTML) }.
- Liens détectés : `[[Note]]`, `[[Note|alias]]`, `[[Note#section]]` †, `[texte](Note.md)`, tags `#tag` et `tags:` dans le frontmatter YAML.
- Résolution des liens comme dans Obsidian (par nom de fichier, insensible à la casse). Un lien vers une note qui n'existe pas
  devient un nœud « fantôme ».
- Sortie : `public/graph.json` { nodes, links } + le contenu complet des notes †.
- Mode live : `chokidar` surveille le vault et régénère le graphe, avec rechargement à chaud.
- Le vault reste en LECTURE SEULE : ne jamais modifier de fichier du vault. †

## Étape 2 : la scène 3D (le cerveau)
- Chaque note = une sphère lumineuse. Sa taille dépend de son nombre de connexions, sa couleur de son dossier racine
  (palette générée automatiquement). Les notes fantômes sont en fil de fer.
- Chaque lien = un trait lumineux (AdditiveBlending, dégradé de la couleur source vers la couleur cible) avec des particules
  qui circulent le long du lien pour montrer son sens.
- Disposition : simulation de forces en 3D avec `d3-force-3d`, puis gel une fois stable. Option : contraindre l'ensemble dans
  une forme de cerveau (deux hémisphères en ellipsoïde).
- Ambiance hologramme : fond très sombre, brouillard (FogExp2), UnrealBloomPass, champ d'étoiles, légère pulsation des sphères,
  scanlines et léger effet de grain en shader pour le côté hologramme. †
- Performance : InstancedMesh pour les sphères, une seule BufferGeometry pour les lignes. Ça doit rester fluide avec 3000+ notes.

## Étape 3 : contrôle avec les mains (le mode « Marvel »)
- Bouton « ✋ Mode mains » (raccourci `H`) : demande la caméra et affiche une PETITE FENÊTRE CAMÉRA flottante en bas à droite †
  (environ 240×180, coins arrondis, effet verre). Elle est déplaçable, et on peut la réduire ou la fermer.
- Dans cette fenêtre : la vidéo en miroir avec le squelette de la main par-dessus (21 points par main, style néon),
  plus le nom du geste détecté en temps réel.
- Utilise MediaPipe Tasks Vision (`@mediapipe/tasks-vision`, HandLandmarker, mode VIDEO, GPU si disponible), avec le modèle
  chargé en local ou depuis le CDN officiel.
- Lisse les positions des mains (filtre One Euro ou équivalent †), avec une zone morte et un petit délai de confirmation des gestes.
- Gestes :
  - Main ouverte qui bouge : faire tourner le cerveau (rotation orbitale qui suit la main).
  - Pincement pouce + index, maintenu : attraper le cerveau et le faire tourner. †
  - Deux mains qui pincent puis s'écartent ou se rapprochent : zoom avant ou arrière (comme Tony Stark).
  - Index pointé : un curseur 3D lumineux (raycast) ; survoler une sphère la met en surbrillance avec ses voisins. †
  - Pincement rapide (« clic ») sur une sphère : la caméra vole vers la note et ouvre son panneau.
  - Poing fermé : figer ou reprendre la rotation automatique.
  - Main qui balaye vers la gauche ou la droite : passer à la note liée précédente ou suivante.
  - Deux mains ouvertes, paumes vers la caméra : recentrer la vue. †
- Retour visuel : anneau autour du curseur qui se remplit pendant un pincement, petit effet d'onde lors d'un clic,
  et le geste actif affiché dans un HUD.
- Tout doit rester utilisable à la souris et au clavier sans caméra. Si l'accès caméra est refusé, afficher un message clair.
- Confidentialité : tout le traitement vidéo se fait localement dans le navigateur, rien n'est envoyé. †

## Étape 4 : interactions classiques
- OrbitControls avec damping, rotation automatique lente quand rien ne bouge.
- Survol : la note et ses voisins s'illuminent, le titre s'affiche. †
- Clic : vol de la caméra avec easing, et panneau latéral avec titre, dossier, tags, nombre de mots, dates, liens entrants et
  sortants cliquables, et le CONTENU COMPLET de la note rendu en HTML. †
- Bouton « Ouvrir dans Obsidian » : `obsidian://open?vault=<NOM>&file=<chemin encodé>`.
- Recherche (raccourci `/`) sur les titres ET le contenu, avec vol vers la note choisie. †
- Filtres par dossier et par tag, masquer les orphelines, masquer les fantômes.
- Touches : `R` recentrer, `Espace` pause de la rotation, `B` forme cerveau, `H` mains, `Échap` fermer. †

## Étape 5 : finitions
- HUD discret : nombre de notes, de liens, d'orphelines, et FPS.
- Légende des couleurs par dossier.
- Interface style hologramme : police mono fine, panneaux en verre dépoli, accents cyan.
- Code modulaire : `parser/`, `scene/`, `ui/`, `hands/` (MediaPipe, lissage, reconnaissance des gestes, mapping vers la caméra). †
- Écris des tests simples pour la reconnaissance des gestes (avec des séries de points simulées). †
- À la fin, donne-moi les commandes exactes : installation, génération du graphe, lancement.
  Explique aussi comment tester le mode mains (bonne lumière, main à 40-80 cm de la caméra).
```

## Tips that made these prompts work

- **Placeholders** (`<CHEMIN/VERS/MON/VAULT>`, `<NOM>`) keep the prompt reusable and free of personal data.
- **Steps, each with a concrete deliverable** (a script, a JSON file, a scene, a gesture list) let the assistant verify one thing at a time.
- **Name your tools** (Vite, Three.js, `d3-force-3d`, MediaPipe, `chokidar`) and your **performance constraints** (3000+ notes, `InstancedMesh`).
- **Ask for tests and for the exact commands at the end.** Gesture logic written as pure functions can be tested with fake landmarks, no camera needed.
- **Say what must never happen** ("the vault stays READ-ONLY") and **what must still work** ("usable with mouse and keyboard without a camera").
